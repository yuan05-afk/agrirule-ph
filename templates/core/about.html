About AgriRulePH

Final Project Documentation, System Scope, and Current Build Status

Project Overview

AgriRulePH is a Django + Supabase PostgreSQL rule-based decision support system designed to help small-scale farmers choose suitable crops using transparent IF-THEN agricultural rules. The system captures farm conditions, computes crop suitability scores, highlights avoid-risk crops, and presents explainable recommendations with decision-oriented analytics.

Current System Capabilities

  • Consultation flow with structured farm inputs: season, soil type, water availability, farm type, soil pH, budget, and crop preference.
  • Rule-based inference engine with positive, negative, and avoid logic for deterministic crop scoring.
  • Results page with top recommendations, confidence labels, explanation traces, condition assessment, action recommendations, and avoid summaries.
  • Expanded recommendation view with top-10 options and trace visibility for deeper review.
  • Decision Analytics page with top recommendation podium, top-10 comparison, category opportunity chart, condition match strength by factor, trade-off comparison, what-if scenarios, suitability tiers, field adjustment opportunities, and insights table.
  • Staff-only dashboard for crop/rule management and consultation records.

How the Rule-Based Method Works

Each crop starts at a base score. Matched positive rules add points, negative rules subtract points, and avoid rules apply strong penalties and avoidance flags. After all active rules are processed, crops are ranked by final score. The system records explanation traces so users can inspect which conditions influenced each recommendation.

Decision Support Focus

AgriRulePH is built to support practical decision-making, not just output rankings. It emphasizes interpretation through recommendation roles, score-gap awareness, avoid risk summaries, and scenario-based sensitivity checks so users can understand both strong options and trade-offs.

Scope and Limitations

  • The system is deterministic and rule-based; it does not use machine learning or predictive probability models.
  • It does not currently integrate real-time weather, pest alerts, geospatial microclimate data, or live market pricing.
  • Outputs depend on entered conditions and the configured rule base; results should be interpreted as decision support guidance.
  • Final planting decisions should still be validated with local agriculture offices and field-specific assessments.
